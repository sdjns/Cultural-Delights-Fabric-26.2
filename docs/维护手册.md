# 维护手册（新手向）

这份文档写给"过几个月再回来改这个模组"的你。按顺序看即可。

---

## 1. 先搞清楚：哪些文件不能丢，哪些随时可以重新生成

| 类型 | 位置 | 能不能删 |
| --- | --- | --- |
| **源码与资源（核心）** | `src/` | ❌ 绝对不能丢 |
| **构建脚本** | `build.gradle`、`settings.gradle`、`gradle.properties`、`gradlew`、`gradlew.bat`、`gradle/` | ❌ 不能丢 |
| **说明文档** | `README.md`、`PORTING-NOTES.md`、`docs/` | ❌ 建议保留 |
| **暂缓的 FD 配方** | `fd_recipe_backup/` | ❌ 建议保留 |
| 构建产物 | `build/` | ✅ 可删，重新构建即可 |
| Gradle 缓存 | `.gradle/` | ✅ 可删，重新构建会重建 |
| 测试服务器世界 | `run/` | ✅ 可删（里面是测试世界） |

> 一句话：**`src/` + 几个 gradle 文件 + 文档 = 你的全部家当**，大概几 MB。

## 2. 日常维护三步

### 第一步：改东西

- 改代码：`src/main/java/com/baisylia/culturaldelights/...`
- 改配方/掉落/标签：`src/main/resources/data/...`
- 改贴图/模型/语言：`src/main/resources/assets/...`
- 加新物品：`item/ModItems.java` + `models/item/<id>.json` + `items/<id>.json` + 语言文件

### 第二步：构建，确认能过

```powershell
# 在 cd-26.2 目录下
.\gradlew.bat build
```

产物在 `build\libs\culturaldelights-<版本>.jar`。
如果第一次跑 `gradlew` 卡在下载 Gradle，直接改用本机已装好的：

```powershell
& "C:\Users\qmy64\Documents\deepseek-harness\default-workspace\cultural-delights-port\gradle-9.7.1\bin\gradle.bat" build
```

### 第三步：备份

双击 `一键备份.cmd`（或运行 `powershell -ExecutionPolicy Bypass -File snapshot.ps1`）。
它会在上一级目录的 `backups\` 里生成：

```
cultural-delights-0.17.8+26.2-20261024-1030.zip
```

压缩包里是**源码 + 文档 + 已构建的 jar + 环境信息**，可以直接换台电脑恢复。

## 3. 三种备份方式，建议组合使用

### 方式 A：本地快照（最简单，已给你配好）

每次改完、构建通过后跑一次 `一键备份.cmd`。
优点：不需要学新东西；缺点：只能回退到你手动备份的那几个时间点。

**建议**：至少保留最近 5 份，旧的可以删。

### 方式 B：Git（已装好并初始化，推荐日常使用）

Git 会给每次提交存一份完整历史，改坏了可以精确回退。

**当前状态**：Git 2.56 已装在 `C:\Users\qmy64\scoop\shims\git.exe`（scoop 管理，已在 PATH 里），
`cd-26.2` **已经是一个 Git 仓库**（已有提交记录，工作区干净）。

日常只需要记住 4 条命令（在 `cd-26.2` 目录下）：

```powershell
git status                  # 看这次改了哪些文件
git add .                   # 把改动加入暂存
git commit -m "改了什么"     # 存一个版本
git log --oneline           # 看历史
```

回退某次改动：`git checkout <提交号> -- .`（提交号用 `git log` 看）。
想看某文件改了什么：`git diff 文件名`。

> 提交身份现在是 `qmy64 <qmy64@localhost>`。以后要推到 GitHub，建议先改成你的邮箱：
> `git config --global user.email "你的邮箱"`。

**备份到 GitHub（异地备份）**：

1. 在 GitHub 新建一个空仓库（不要勾选 README）；
2. 在 `cd-26.2` 里执行：
   ```powershell
   git remote add origin https://github.com/你的用户名/仓库名.git
   git push -u origin main
   ```
3. 之后每次 `git push` 即可同步。

### 方式 C：异地备份（防硬盘坏）

把 `backups\` 里的 zip 复制到网盘（OneDrive/百度网盘）或移动硬盘。
**至少留一份在另一块物理设备上**。

| Fabric Loader | 0.19.5 |

换电脑恢复步骤：

1. 装 **JDK 25**；
2. 解压备份 zip；
3. 在项目目录运行 `gradlew.bat build`（第一次需要联网下载依赖，约 500 MB 缓存）；
4. 产物在 `build\libs\`。

> 可以在 `C:\Users\<你>\.gradle\gradle.properties` 里加代理，例如：
> ```
> systemProp.https.proxyHost=127.0.0.1
> systemProp.https.proxyPort=7890
> ```

## 5. 常见维护任务

### 改一个食物数值

`src/main/java/com/baisylia/culturaldelights/item/ModFoods.java`：

```java
public static final FoodProperties AVOCADO = new FoodProperties.Builder()
        .nutrition(4)          // 饥饿值
        .saturationModifier(0.6F) // 饱和度系数
        .build();
```

### 加一个新食物物品

1. `ModFoods.java` 加数值；
2. `ModItems.java` 加一行 `ModRegistries.simpleItem("my_food", new Item.Properties().food(ModFoods.MY_FOOD));`
3. `assets/culturaldelights/models/item/my_food.json`（`item/generated` + 贴图）
4. `assets/culturaldelights/items/my_food.json`（26.2 必须）
5. 贴图放 `textures/item/my_food.png`，语言文件加名称；
6. 想让它出现在创造页：`tab/ModCreativeModeTabs.java` 里 `output.accept(ModItems.MY_FOOD);`

### 改版本号

`gradle.properties` 里的 `mod_version=0.17.8+26.2`，改完重新构建。

### 等 Farmer's Delight 出了 26.2，恢复完整联动

1. 把 `fd_recipe_backup/culturalrecipes/recipe/` 放回 `src/main/resources/data/culturalrecipes/recipe/`；
2. 把 `fd_recipe_backup/farmersdelight/` 放回 `src/main/resources/data/farmersdelight/`；
3. `build.gradle` 加 FD 依赖，把 `SimpleFeastBlock` / `WildCropBlock` 换回 FD 的 `FeastBlock` / `WildCropBlock`。

## 6. 出问题怎么查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 编译报错 `package net.minecraft.core does not exist` | Loom 没生成 Minecraft 依赖 | 确认 `build.gradle` 里有 `loom { splitEnvironmentSourceSets() }`（已配好），然后 `gradlew.bat clean build` |
| 进游戏显示紫黑方块 | 缺 `items/<id>.json` 或模型路径不对 | 对照 `assets/culturaldelights/items/` 与物品 id |
| 配方不生效 | 材料格式写错（26.2 是字符串 `"minecraft:wheat"` / `"#c:tag"`） | 看服务器日志 `Couldn't parse data file` |
| 世界生成没出现 | 群系没写进 `world/BiomeModifications`，或 feature JSON 名字对不上 | 看日志里的 `Unknown registry key` |
